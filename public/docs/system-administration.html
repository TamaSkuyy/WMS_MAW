1. User Management

Modul untuk mengelola akun login pengguna sistem. Akses: sidebar Setup → Users atau /users. Hanya Superadmin.

Permission — Users

PermissionFungsi
view usersLihat daftar user, export
manage usersTambah, edit, hapus user, import
Screenshot: Halaman Users — tabel: Nama, Email, Role badges, Employee link, Aksi

Mengelola User

Menambah User (Manual)

  1. Klik Tambah User. Isi: Nama, Email, Password, Role.
  2. Role bisa dipilih manual dari dropdown.
  3. Opsional: kaitkan dengan Employee (employee_id) — role akan otomatis mengikuti Job Position.
  4. Simpan. User bisa langsung login.

Alternatif: Generate User dari Employee

User juga bisa dibuat dari modul Employee → Generate User (lihat manual Employee Management). Ini lebih disarankan karena role otomatis mengikuti jabatan.

⚠️ Edit User & Role Mengubah role user langsung di halaman Users akan menimpa role yang di-assign otomatis dari Job Position. Untuk menjaga konsistensi, sebaiknya kelola role melalui Job Position (Employee module), bukan langsung di User.

2. Role & Permission (RBAC)

WMS MAW menggunakan Spatie Laravel Permission — sistem Role-Based Access Control dengan ~74 permission yang mengatur akses ke setiap fitur.

3 Role Bawaan

RoleBadgePermissionDeskripsi
superadmin SUPERADMIN Semua (74) Akses penuh. Kelola user, role, permission, menu. Hanya 1-2 orang.
leader LEADER ~50 View semua master data, full CRUD transaksi, akses report & monitoring. Tidak bisa hapus master data & tidak bisa akses system admin.
operator OPERATOR ~20 View master data terbatas, create receiving & shopping. Tidak bisa edit/delete/ship. Role harian gudang.

Mengelola Role & Permission

Mengedit Role (Setup → Roles)

  1. Buka /roles. Tabel menampilkan semua role dengan daftar permission-nya.
  2. Klik Edit pada role yang ingin diubah.
  3. Centang/uncentang permission di daftar checkbox (dikelompokkan per modul).
  4. Simpan. User dengan role ini akan mendapatkan permission baru setelah logout & login ulang.

Melihat Daftar Permission (Setup → Permissions)

Halaman /permissions menampilkan semua permission yang terdaftar di sistem. Hanya read-only untuk melihat. Permission dibuat melalui database seeder (WmsRoleSeeder).

⚠️ Jangan edit role Superadmin sembarangan Role superadmin harus selalu punya SEMUA permission (manage roles, manage permissions). Jika tidak sengaja menghapus permission dari superadmin, kamu bisa terkunci dari halaman Roles itu sendiri. Jalankan ulang seeder untuk recovery.

3. Menu & Sidebar Configuration

Modul untuk mengelola tampilan sidebar navigasi. Setiap menu item bisa dikaitkan dengan permission — user hanya melihat menu yang sesuai dengan permission-nya. Akses: Setup → Menu Management atau /menus.

Permission — Menu

PermissionFungsi
view menusLihat struktur menu
manage menusTambah, edit, hapus menu items
Screenshot: Halaman Menu Management — tabel hierarki: Parent Menu → Sub Menus, dengan icon, path, permission_name, sort_order

Struktur Menu

FieldKeterangan
NameLabel yang muncul di sidebar
IconNama icon (Heroicons). Contoh: BoxIcon, TagIcon
PathURL tujuan. Contoh: /suppliers. Kosongkan untuk parent menu.
ParentParent menu (null = menu level atas)
Sort OrderUrutan tampilan. Angka kecil = di atas.
Permission NamePermission yang diperlukan untuk melihat menu ini. Contoh: view suppliers
Groupmain = sidebar utama. others = group Setup (hanya superadmin).

Mengelola Menu

Menambah Menu Baru

  1. Klik Tambah Menu.
  2. Isi Name, Path, Icon, Permission Name, Sort Order.
  3. Pilih Parent jika ini sub-menu.
  4. Pilih Group: main (terlihat semua user) atau others (hanya superadmin).
  5. Simpan.
💡 Cara kerja filtering menu Setiap kali user login, sistem memeriksa setiap menu item:
• Jika menu punya permission_name, cek apakah user punya permission tersebut via $user->can(...).
• Jika user TIDAK punya permission → menu disembunyikan.
• Parent menu tanpa path akan disembunyikan jika SEMUA sub-menunya juga tersembunyi.

Ini memastikan setiap user hanya melihat menu yang relevan dengan role-nya.

Troubleshooting

🚫 Tidak bisa akses Setup menu

Penyebab: Hanya superadmin yang bisa melihat menu Setup (Users, Roles, Permissions, Menus).

Solusi: Login dengan akun superadmin (admin@maw.com).

🔘 Tombol tidak muncul padahal role sudah diubah

Penyebab: Permission di-cache. User harus logout & login ulang setelah role berubah.

Solusi: Logout → login kembali. Jika masih bermasalah di production, restart container (docker compose restart app) untuk clear Octane memory cache.

🔐 Terkunci dari halaman Roles (tidak sengaja hapus permission sendiri)

Penyebab: Role superadmin kehilangan manage roles atau view roles.

Solusi: Jalankan seeder ulang di server:
php artisan db:seed --class=WmsRoleSeeder --force
php artisan optimize:clear
Restart container app, lalu login ulang.

📋 Menu baru tidak muncul di sidebar

Penyebab: Bisa jadi permission_name tidak cocok, atau user tidak punya permission tersebut, atau lupa set sort_order.

Solusi: Cek permission_name di menu — harus sama persis dengan nama permission di database. Cek apakah user kamu punya permission tersebut.

👥 User tidak bisa login / role hilang

Penyebab: Bisa karena syncRoles dari Job Position menimpa role manual.

Solusi: Cek apakah user terkait Employee. Jika iya, role dikelola oleh Job Position, bukan manual di User. Edit Job Position untuk mengubah role.
